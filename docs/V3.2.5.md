# V3.2.5 — navigation dans l’onglet courant

Retour utilisateur réel du 21 novembre 2026 : GM_openInTab ouvre encore l’app Vinted, et le lien spécial Orion retourne Invalid URL. Ces méthodes n’ont donc pas résolu le routage sur cet iPhone. Le format d’encodage du schéma n’est pas précisé par Orion et aucune variante fiable n’a pu être confirmée. Les deux méthodes sont retirées.

## Correction

Le bouton appelle **window.location.assign** sur l’URL HTTPS Vinted complète avec le même identifiant en fragment. Aucun lien spécial, aucune ancre HTTPS déclenchée, aucun window.open, aucun nouvel onglet par l’extension. Le grant GM_openInTab est retiré. Le code de remplissage, la communication locale, les contrôles des champs, les photos et le stockage catalogue restent inchangés.

Un ingénieur Apple confirme que window.location depuis une extension Safari est traité comme un collage dans la barre d’adresse et charge le site : [réponse Apple DTS](https://developer.apple.com/forums/thread/776365). Cette observation concerne Safari, pas une garantie pour toutes les versions d’Orion. **La 3.2.5 doit encore être essayée sur son iPhone.** Aucun contournement des protections Vinted n’est impliqué.

Le guide inclut la vraie préférence Orion : **Réglages → General → App Opener**. Retirer uniquement la règle vinted.es / www.vinted.es par balayage droite-gauche, ou la remettre sur Ask/Preguntar, puis retenter le bouton et choisir **Never/Nunca**. Ne pas effacer les données de site ni désinstaller Vinted ou Orion. [Chemin et geste reproduits par l’équipe sur iOS](https://orionfeedback.org/d/11419-overlapping-text-in-app-opener), [chemin confirmé sur 1.5.5](https://orionfeedback.org/d/14641-apollo-no-longer-available-in-app-opener), [mémorisation de Never](https://orionfeedback.org/d/14721-open-links-in-prompt-suggests-apps-that-arent-installed/1).

Si le système ouvre encore l’app, le lien complet reste copiable dans la barre d’adresse Orion ; ce secours garde l’identifiant. Après une connexion perdant ce fragment, la reprise est explicite via le bouton compact Orion puis Rellenar una sola vez. Aucun second lancement automatique ni publication.

Aucun schéma personnalisé dans les liens ou copies, aucun nouvel hôte de stockage.

## Vérification

- Node : URL/nonce encodées, assign dans l’onglet courant, erreur propagée, aucune API d’ouverture alternative, ACK inchangés.
- WebKit/Chromium contrôlés : navigation réelle du catalogue au formulaire dans la même page, nombre de pages conservé, titre/description/prix/catégorie/état/marque/colis finaux et octets/ordre des deux photos ; aucune publication ; reprise sans double photo et après perte de fragment.
- Fixture de faute distincte : le test remplace uniquement l’instruction de navigation pour simuler une interception OS. Il vérifie absence de faux succès/seconde ouverture et réception tardive. Il ne simule pas la gestion native des liens par iOS.
- Dashboard : URL HTTPS exacte, pas de schéma personnalisé, guide conditionné à Orion par défaut, ES/FR, copie et stockage V1 préservé.
- CI : suite complète et build reproductible avant livraison.

Aucun test automatisé ne constitue une preuve du routage natif sur le téléphone de l’utilisatrice. Il faut connaître sa version d’Orion et essayer la navigation après vérification de la règle App Opener.
