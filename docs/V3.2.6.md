# V3.2.6 — catégorie, état et colis

21 novembre 2026. L’utilisateur confirme que l’ouverture reste maintenant dans le navigateur. Le lien et la logique de navigation 3.2.5 ne sont pas modifiés.

## Constats et corrections

Le code sautait l’état, la marque et le colis lorsqu’une catégorie n’était pas confirmée. Cela peut produire les trois symptômes à partir d’un seul échec ; ce lien est démontré dans le code, mais les valeurs de la fiche du téléphone n’ont pas été communiquées. Aucune valeur de remplacement n’est devinée.

Deux erreurs de portée ont été corrigées : un aria-controls pointant vers un vieux popover caché ne doit pas cacher le dialogue mobile actif ; une listbox interne ne doit pas exclure le pied contenant Fait. Les éléments masqués par aria-hidden, inert, hidden ou CSS sont ignorés. Une reprise peut retrouver le champ principal masqué par ReactModal, sans le cliquer derrière la fenêtre. Fait/Listo/Hecho doit être actif, le radio et le composant sélectionnés, puis le dialogue fermé et le champ principal accessible.

Le bouton de préparation utilisait auparavant l’objet capturé lors de l’ouverture de l’aperçu. Il relit maintenant IndexedDB avant de créer le transfert, ce qui préserve les dernières modifications faites dans un autre onglet. Les trois chaînes source sont affichées avant l’ouverture et dans Vinted, sans traduction du contenu des fiches.

Les photos sont transmises avant les caractéristiques. Les indicateurs visibles progressbar/aria-busy sont attendus avec une borne de 15 secondes et 900 ms de stabilité. Cela ne prouve pas qu’une plateforme a accepté les images ; les miniatures natives restent à vérifier. L’état précis est revérifié avant le choix du colis. La fonction d’injection photo, les octets et l’ordre des fichiers restent inchangés. En reprise sans photos, la catégorie est traitée avant les textes pour sortir d’un modal déjà ouvert.

Le colis dispose d’une liste précise dans la fiche : Petit/Pequeño, Moyen/Mediano, Grand/Grande. Un ancien alias reconnu est conservé littéralement ; une ancienne valeur inconnue reste affichée à préciser, sans défaut Moyen. Le stockage n’est pas migré.

## Contrôle actuel et limites

Le panneau affiche **Fiche enregistrée / Lu dans Vinted / Contrôle** pour catégorie, état et colis. Un observateur et une lecture périodique retirent le succès si une valeur est réinitialisée tardivement. Ils n’ouvrent pas de menu, ne cliquent pas, ne lisent pas les photos et ne remplacent pas les modifications manuelles de l’utilisateur. En cas d’échec, le détail de la dernière tentative accompagne la raison actuelle ; il disparaît quand la valeur est effectivement vérifiée. Le suivi reprend après restauration de page par le cache de navigation. L’effacement du transfert arrête ce suivi.

Pour une catégorie avec chemin complet, la feuille affichée ne suffit pas : une preuve locale du choix de la bonne ligne est exigée. La preuve est invalidée quand le menu catégorie est rouvert. Un choix manuel ultérieur au même libellé ne prouve pas la branche choisie. Si la valeur manque, si Neuf/Nuevo est ambigu ou si le composant n’accepte pas la sélection, le contrôle reste à confirmer. Les attributs supplémentaires non modélisés restent manuels.

## Vérifications distinctes

- **Observation réelle Vinted Espagne / Chrome**, compte connecté, largeur CSS 390 : dialogue mobile Catégorie avec group/radios et pied Fait ; sélection de Jeux de société sous Loisirs et collections puis Fait ; dialogue État avec les cinq libellés français précis, sélection native de Neuf sans étiquette, radio checked et aria-checked vrais, Fait actif puis fermeture ; Petit choisi à la place de la suggestion Moyen avec un seul radio actif. Aucune saisie de fiche privée, aucune photo envoyée, aucun clic Ajouter/Sauvegarder. Les interactions sont natives, pas une exécution du userscript mis à jour sur un iPhone.
- **Tests contrôlés WebKit/Chromium** : dialogues et confirmations, ancien popover masqué, reprise avec fond aria-hidden, absence de faux succès, état FR/ES, format de colis, photo/loading, reset tardif, comparatif UI, arrêt de l’observateur, ancien aperçu et valeurs littérales. Les tests vérifient les valeurs, pas seulement le déclenchement de clics.
- **Non-régression** : CRUD, migrations V1/V2/V3, sauvegardes/restauration, quota et photos, stock, langues, lancement même onglet, métadonnées et build reproductible. `src/core.js` et la fonction de transfert de fichiers ne sont pas modifiés.
- **NON VALIDÉ** : exécution de 3.2.6 dans Orion/Violentmonkey sur le téléphone de l’utilisatrice, identité exacte de ses trois valeurs et tous les délais/réponses Vinted. Une confirmation sur le vrai site Chrome ne prouve pas les événements générés par un userscript sur Orion iOS.

Les captures privées du compte connecté restent hors dépôt. Les anciennes versions sont conservées. La publication et la sauvegarde distante du brouillon restent exclusivement manuelles.
