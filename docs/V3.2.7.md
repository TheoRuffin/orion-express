# V3.2.7 — vérification et correction automatiques

22 novembre 2026. Le parcours reste sélection du produit → Préparer sur Vinted → ouverture dans le même onglet. Aucun bouton, réglage ou écran de confirmation n’est ajouté.

## Session de préparation

La première passe reste protégée par le verrou navigateur et les marqueurs locaux par transfert. Les photos ne passent qu’une fois dans le sélecteur. Le script remplit ensuite les champs connus, puis compare le formulaire actuel à la fiche : titre et description exacts (hors CRLF), prix en centimes, catégorie avec preuve de chemin lorsqu’il est fourni, marque, état précis et colis exclusif. Les erreurs natives `validity`, `aria-invalid` et erreurs visibles associées empêchent un succès.

Les champs perdus ou réinitialisés par le site sont corrigés sans nouvelle action : **deux reprises supplémentaires maximum par champ**, dans une **session de 60 secondes** à partir du début de la tentative. Une réparation commence par le menu déjà ouvert, puis la catégorie et ses dépendants. Des textes/prix possédés par la préparation peuvent être corrigés indépendamment d’une catégorie non résolue, s’ils restent accessibles. Après une passe, les sept valeurs doivent rester correctes durant 1,4 seconde. Le suivi existant continue à relire les valeurs ; dans le temps et le budget restants, un nouvel écart déclenche une correction après 500 ms. Les limites empêchent les boucles et les clics sans fin ; elles ne constituent pas une garantie du site.

La correction des textes/prix est réservée aux champs initialement vides, déjà identiques ou effectivement renseignés par cette préparation. Un texte antérieur différent n’est pas écrasé. Les choix ambigus, notamment Neuf/Nuevo, ne sont pas devinés.

## Arrêts et interruptions

Un geste utilisateur fiable dans un contrôle natif (pointeur, clic, clavier, saisie) arrête les écritures de cette session ; les clics synthétiques du script ne déclenchent pas cet arrêt. Le panneau garde son audit en lecture seule. Les interactions avec le bouton compact Orion ne modifient pas les valeurs natives. Une reprise explicite avec le bouton existant crée une nouvelle session, toujours sans nouvelle injection photo.

La garde vérifie le contexte avant chaque mutation et reste installée jusqu’à la fin de l’opération asynchrone. Une confirmation retardée ne peut donc pas cliquer Fait après arrêt. Une navigation hors formulaire ou un nonce différent met fin à l’ancienne session. Hors connexion ou page masquée, les écritures sont suspendues ; le retour connecté/visible peut reprendre dans le temps restant. Un rechargement conserve les protections anti-doublon, sans prétendre reprendre automatiquement un envoi photo interrompu. Le retour via cache de navigation conserve le suivi.

## Photos et validation finale

Les métadonnées locales des fichiers (nom ordonné, nombre, taille, type, date) sont comparées au manifeste préparé. Cela prouve seulement la remise au sélecteur : **ni FileList ni l’absence de progressbar ne prouvent l’acceptation des miniatures par Vinted**. Si l’input est vidé par le site, le script ne réinjecte pas automatiquement les photos. Les originaux, les octets et leur ordre restent conservés dans le catalogue et ses sauvegardes.

Le comparatif couvre les huit lignes, plus les champs supplémentaires visiblement invalides lorsque le formulaire expose ces contrôles. Les erreurs et différences empêchent un ACK complet. Sans preuve de l’acceptation native des photos, la préparation reste explicitement partielle, même si les sept autres champs sont corrects. Les attributs supplémentaires non modélisés restent à vérifier. Aucune API privée, aucun clic Ajouter/Publier/Sauvegarder ni rechargement automatique du formulaire.

## Tests et limites

Les tests contrôlés WebKit et Chromium simulent des composants dynamiques, remplacements de nœuds, effacement tardif des sept valeurs, erreurs de validation, budgets épuisés, modals mobiles, gestes utilisateur réellement trusted, perte de connexion, visibilité et changement de nonce. Ils vérifient les valeurs finales, la conservation des fichiers et l’absence de publication. CRUD, migrations, sauvegardes, stock, langues, métadonnées et build reproductible restent couverts par la suite existante.

**NON VALIDÉ :** cette version sur un iPhone réel dans Orion/Violentmonkey, les réponses du serveur Vinted et l’acceptation native de toutes les photos. Les observations natives Chrome antérieures ne valident pas ces nouveaux automatismes sur iOS. Le navigateur et les interfaces publiques ne permettent pas de promettre une réussite à 100 % ; un refus persistant demeure signalé.
